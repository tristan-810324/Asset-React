# A.SSET GSO System
## Business Process Automation and Feature Roadmap

### Consolidated proposal

Ang document na ito ang consolidated at filtered version ng [otherfeatures.md](./otherfeatures.md) at [features2.0.md](./features2.0.md). Pinili lamang dito ang mga feature at automation na pinakamalapit sa kasalukuyang ginagawa ng A.SSET system.

Ang pangunahing direction ay gawing **GSO Request-to-Resolution Automation System** ang project: mula sa digital request sa home page, automatic validation, GSO review, reservation, release, return, repair, hanggang closure at reporting.

> Planning document lamang ito. Wala itong code implementation.

---

## 1. Kasalukuyang System Context

Ang mga feature na pinakamalinaw na bahagi ng project ngayon ay:

- authentication at email verification;
- IT Admin at GSO Staff roles;
- user management at audit logs;
- employee master data;
- inventory items, categories, quantities, conditions, at statuses;
- issuance records at issuance quantities;
- returns at partial returns;
- items for repair;
- GSO dashboard; at
- `Requests & Borrowing` page na maaaring gawing live workflow.

Dahil dito, ang pinakamalaking value ay hindi muna sa pagdagdag ng maraming unrelated modules. Mas bagay na unang i-connect ang mga existing modules sa iisang automated request process.

## 2. Feature Filter: Ano ang Dapat Unahin

| Priority | Scope | Bakit bagay sa current system |
|---|---|---|
| Must Have Now | Home page GSO Request Center | Ito ang entry point ng students, faculty, employees, at offices |
| Must Have Now | Borrowing MVP | Direktang konektado sa inventory, issuance, returns, quantity, at condition |
| Must Have Now | GSO approval queue | May existing GSO Staff role at Requests & Borrowing page |
| Must Have Now | Availability at reservation | Kailangan para maiwasan ang double booking at maling stock |
| Must Have Now | Release, return, overdue, at repair triggers | Tugma sa existing issuance, returns, at repair flow |
| Must Have Now | Notifications, audit, at secure access | May authentication, email verification, at audit foundation na ang system |
| Next | Policy configuration, SLA, reports, QR/barcode | Nagpapalakas sa automation kapag stable na ang MVP |
| Future | Facility, vehicle, at purchase requests | Magandang expansion, pero dapat gumana muna ang core borrowing workflow |
| Not Yet | Anonymous public borrowing, automatic penalties, AI auto-approval, full procurement system | Mataas ang risk at hindi kailangan para sa unang release |

### Main recommendation

Unahin ang isang complete process na gumagana mula simula hanggang dulo:

```text
Home Page Form
    -> Validate
    -> GSO Queue
    -> Approve
    -> Reserve
    -> Release
    -> Monitor
    -> Return
    -> Inspect
    -> Close
```

Kapag stable na ito, maaaring gamitin ang parehong pattern para sa ibang GSO services.

## 3. Home Page GSO Request Center

### Main feature

Maglagay sa home page ng prominent section na maaaring tawaging:

- **GSO Services**
- **Submit a GSO Request**
- **Request Center**
- **Need something from GSO?**

Ang home page ay magiging public entry point para sa request forms, ngunit hindi public ang GSO dashboard. Ang normal user ay maaaring mag-submit at mag-track ng sariling request lamang.

### Recommended service cards for the first release

1. **Borrow an Item**
   - Laptop, projector, chair, table, sound system, at iba pang approved equipment.

2. **Request a GSO Service**
   - Setup, repair, installation, hauling, cleaning, o ibang GSO service.

3. **Report Damaged or Missing Item**
   - Damage, lost item, missing accessory, o return discrepancy.

4. **Track My Request**
   - Status, timeline, GSO note, schedule, revision, at next action.

### I-hold muna para sa future phase

Ang mga ito ay maaaring ilagay pagkatapos gumana ang Borrowing MVP:

- Reserve a Facility
- Request a School Vehicle
- Submit a Purchase Request

Hindi ibig sabihin na tatanggalin ang mga ito. Mas maayos lamang na hindi muna sila maging pangunahing workflow habang hindi pa finalized ang borrowing rules.

### Dynamic home page form automation

Kapag pumili ang user ng service card:

- ipakita lamang ang fields na relevant sa service;
- i-pre-fill ang verified name, email, department, course, o employee number;
- i-adjust ang fields ayon sa Student, Faculty, Employee, Office, o Organization;
- ipakita ang required attachments;
- i-check ang dates, quantity, availability, at possible conflict;
- mag-save ng draft kung hindi pa tapos ang user;
- mag-warning kapag posibleng duplicate ang request;
- gumawa ng request code pagkatapos ng successful submit; at
- i-route ang request sa tamang GSO queue.

### Access rule

- Ang user ay kailangang naka-sign in o makapag-verify ng school email bago ang final submission.
- Ang student ay maaaring hingan ng student number, course, year level, section, at adviser kung kailangan.
- Ang faculty o employee ay maaaring hingan ng employee number, department, at supervisor kung kailangan.
- Ang office/organization representative ay kailangang may authorized office information.
- Ang GSO Staff lamang ang may access sa full request queue, approval, reservation, release, at inspection.

## 4. Borrowing MVP: Primary Business Process

### 4.1 Digital borrowing form

#### Requester information

- Full name
- User type
- Student number o employee number
- Course, year level, section, o department
- School email
- Mobile number
- Adviser, supervisor, o requesting office kung required

#### Borrowing information

- Item o item category
- Quantity
- Purpose o activity
- Location ng paggamit
- Pickup date and time
- Expected return date and time
- Event name kung applicable
- Number of participants kung applicable
- Special instructions
- Required endorsement, permit, o approval attachment

#### Accountability confirmation

- Confirmation na nabasa ang borrowing rules.
- Digital acknowledgment o e-signature.
- Confirmation ng contact details.
- Agreement na pananagutan ng borrower ang item habang naka-checkout.

### 4.2 Borrower eligibility matrix

Gawing configurable ang rules. Hindi dapat pareho ang permission sa lahat ng item categories.

| Requester | Standard shared item | High-value IT equipment | Restricted/fragile item | Suggested approval |
|---|---|---|---|---|
| Student | School-related use at available items | Case-to-case, may adviser/office approval | Karaniwang restricted | GSO Staff plus required adviser/office |
| Faculty | Class, event, o official work | Puwede kung authorized | May special handling rule | GSO Staff o supervisor |
| Employee | Official office work | Puwede kung authorized | May special handling rule | GSO Staff o department supervisor |
| Office/Organization | Approved school activity | May authorized representative | Case-to-case | Office head/supervisor plus GSO |
| External requester | Manual verification lamang | Hindi default na allowed | Hindi default na allowed | GSO supervisor |

> Sample policy lamang ang table. Dapat i-finalize ng GSO ang actual allowed items, quantity, duration, at approval path.

### 4.3 Item policy settings

Bawat item category ay dapat magkaroon ng configurable settings:

- allowed requester types;
- maximum quantity;
- maximum borrowing duration;
- required attachment;
- required approval level;
- overnight borrowing rule;
- extension allowed o hindi;
- maximum number of extensions;
- release checklist;
- return checklist;
- high-value/restricted/fragile flag; at
- required condition photos.

Mas mainam na configurable ang rules kaysa hardcoded upang mabago ng authorized GSO o IT Admin kapag nagbago ang policy.

### 4.4 Approval at release permissions

| Role | Allowed actions | Restricted actions |
|---|---|---|
| Requester | Submit, view own request, upload revision, cancel before release, request extension | Approve sariling request o baguhin ang inventory status |
| GSO Staff | Review, validate, approve standard request kung authorized, reserve, prepare release, record release/return | Override restricted policy nang walang permission |
| GSO Supervisor | Approve high-value/restricted request, approve extension, resolve damage/loss, authorize override | Burahin ang audit history |
| IT Admin | Manage users, roles, permissions, settings, at audit access | Mag-approve o mag-release ng GSO item by default |

Magkaroon ng action-based permissions para sa:

- view request;
- approve request;
- reserve item;
- release item;
- record return;
- approve extension;
- resolve incident;
- download attachment; at
- export report.

### 4.5 Availability at reservation

Kapag nag-submit ng borrowing request:

1. I-check ang available quantity.
2. I-check ang active borrowing at confirmed reservations.
3. I-check ang maintenance status.
4. I-check ang date/time conflict.
5. Kung available, gumawa ng temporary reservation hold.
6. Lagyan ng expiration ang hold.
7. Kapag approved, gawing confirmed reservation ang hold.
8. Kapag rejected, cancelled, expired, o no-show, i-release ang hold.
9. Kapag actual na nailabas ang item, saka lamang maging `Borrowed` o `Issued`.

### Inventory rules

- Bawal pumili ng `Under Maintenance`, `Unserviceable`, o `Retired` item.
- Hindi maaaring lumampas ang requested quantity sa available quantity.
- Hindi maaaring magkaroon ng double booking.
- Ang approved request ay hindi pa actual release.
- Ang temporary hold ay dapat ma-expire at ma-release kapag hindi na valid.
- Dapat ma-record ang before/after quantity at status sa audit trail.

### 4.6 Status workflow

| Status | Meaning |
|---|---|
| Draft | Sinimulan ngunit hindi pa submitted |
| Submitted | Natanggap na ng system |
| For Review | Nasa GSO queue |
| Needs Revision | May kulang o kailangang baguhin |
| Approved | Inaprubahan ngunit hindi pa nailalabas |
| Reserved | May confirmed quantity at schedule |
| Ready for Pickup | Puwede nang kunin sa pickup window |
| Borrowed / Active | Nasa borrower na ang item |
| No-show Warning | Hindi dumating o hindi nag-confirm |
| Extension Pending | May hinihintay na extension decision |
| Overdue | Lumampas sa due date |
| Partially Returned | May natitirang quantity |
| For Inspection | Naibalik ngunit kailangang i-check |
| Incident Review | May damage, loss, o mismatch |
| Closed | Kumpleto na ang process |
| Rejected | Hindi inaprubahan, may reason |
| Cancelled | Kinansela bago matapos ang process |

### 4.7 Release automation

Kapag pinindot ng authorized GSO Staff ang **Prepare for Release**, awtomatikong ihahanda ng system ang:

- request code;
- borrower identity;
- item code at description;
- approved quantity;
- pickup schedule;
- accessories checklist;
- condition-out fields;
- releasing staff field; at
- digital acknowledgment.

Sa actual release:

- itala ang release date/time;
- itala ang quantity na nailabas;
- itala ang condition out;
- itala ang releasing staff;
- i-update ang inventory quantity/status;
- gumawa ng release receipt; at
- magpadala ng notification sa borrower.

### 4.8 Return automation

Sa actual return:

- itala ang returned quantity;
- i-compare sa released quantity;
- kalkulahin ang remaining quantity;
- itala ang condition in;
- i-record ang return date/time;
- i-attach ang photos kung required;
- i-update ang inventory status;
- gumawa ng repair/incident task kung kailangan; at
- magpadala ng return acknowledgment.

### 4.9 Partial return

Kung hindi kumpleto ang return:

- gawing `Partially Returned` ang borrowing;
- manatiling active ang unreturned quantity;
- huwag i-mark na fully available ang buong quantity;
- gumawa ng follow-up reminder;
- ipakita ang remaining quantity sa GSO dashboard; at
- i-close lamang kapag zero na ang remaining quantity o may approved incident resolution.

### 4.10 No-show

Kapag hindi dumating ang borrower sa pickup schedule:

1. Ilagay sa `No-show Warning`.
2. Magpadala ng reminder sa grace period.
3. Kapag lumampas sa grace period, i-release ang reservation.
4. Ibalik ang item sa available pool kung walang ibang issue.
5. I-record ang no-show sa request history.
6. Mag-flag para sa manual review kapag paulit-ulit.

Hindi dapat agad i-blacklist ang user sa unang no-show. Dapat configurable ang threshold at may GSO override.

### 4.11 Extension

Ang extension ay dapat panibagong request action, hindi simpleng pagpapalit ng due date.

1. Mag-request ang borrower bago ang due date.
2. Pumili ng bagong return date at maglagay ng dahilan.
3. I-check ang availability at future reservations.
4. Kung may conflict, hindi papayagan ang automatic extension.
5. Kung low-risk at walang conflict, dumaan sa simplified GSO review.
6. Kung high-value o restricted, kailangan ng supervisor approval.
7. Magpadala ng decision notification.
8. I-record ang extension sa audit trail.

Safeguards:

- maximum number of extensions;
- maximum total borrowing duration;
- bawal ang extension kapag overdue na maliban sa manual override;
- bawal ang extension kapag may pending damage/loss incident; at
- bawal ang extension kung may confirmed reservation ng ibang user.

## 5. Automation Rules at Business Process Table

| Trigger | Automatic system action | Human owner | Output |
|---|---|---|---|
| User submits form | Validate fields, attachments, identity, dates, quantity | Requester kung may error | Complete request o revision warning |
| Valid submission | Create request code and timeline | System | Submitted request |
| Request created | Route by type and policy | GSO Staff | GSO queue item |
| Item selected | Check quantity, status, and conflict | System | Available or unavailable result |
| Request for review | Suggest approval path | GSO Staff/Supervisor | Review task |
| Approved request | Create confirmed reservation | GSO Staff | Reserved item |
| Pickup window approaching | Send reminder and request confirmation | Requester | Confirmed or pending pickup |
| Authorized release | Update inventory and issuance record | GSO Staff | Borrowed/Issued item |
| Due date approaching | Send return reminder | Borrower/GSO | Return action |
| Due date passed | Mark overdue and escalate | GSO Staff/Supervisor | Overdue task |
| Return recorded | Compare quantity and condition | GSO Staff | Inspection or closure task |
| Damage detected | Create repair/incident task | GSO Staff/Supervisor | Blocked item and incident |
| Complete return | Update stock and close request | GSO Staff | Closed request |
| SLA exceeded | Send reminder and escalate | Assigned staff/Supervisor | Needs Attention item |

## 6. Notifications, Escalations, at SLA

### Event-based notifications

| Event | Recipient | Notification |
|---|---|---|
| Request submitted | Requester and GSO queue | Confirmation at request code |
| Needs revision | Requester | Required changes o missing attachment |
| Approved | Requester and GSO | Pickup instructions |
| Rejected | Requester | Decision reason |
| Pickup approaching | Requester | Pickup reminder |
| No-show warning | Requester and GSO | Grace period warning |
| Item released | Requester | Release receipt at due date |
| Due date approaching | Requester | Return reminder |
| Overdue | Requester, GSO, supervisor | Overdue alert and escalation |
| Extension decision | Requester | Approved/rejected extension |
| Return recorded | Requester | Return acknowledgment |
| Damage/loss found | GSO and authorized reviewer | Incident review alert |
| Request closed | Requester | Completion notice |

### Suggested SLA settings

Ang values ay configurable at dapat i-finalize ng GSO:

- initial review within one working day;
- decision within three working days;
- revision response within two working days;
- pickup confirmation before the pickup window;
- overdue follow-up after one working day; at
- repair assessment within two working days.

Kapag lumampas sa SLA:

1. Magpadala ng reminder sa assigned staff.
2. I-flag sa `Needs Attention` dashboard.
3. Mag-escalate sa GSO supervisor.
4. I-record ang escalation sa audit trail.

### Notification reliability

- In-app notification ang source of truth.
- Email ang additional channel.
- Mag-record ng Pending, Sent, Failed, at Retried status.
- Mag-retry kapag temporary ang email failure.
- Hindi dapat mawala ang request kapag failed ang email.
- Hindi dapat magpadala ng duplicate alert sa bawat page refresh.
- Gumamit ng secure link para sa sensitive request details.

- reservation near expiry;
- unconfirmed pickup;
- overdue borrowing;
- extension pending;
- partial return;
- damaged/missing item;
- failed notification; at

### 8.3 Policy configuration

Para maging tunay na BPA system, dapat may configurable settings para sa:

- allowed borrower per item category;
- maximum quantity;
- borrowing duration;
- approval level;
- pickup grace period;
- no-show threshold;
- extension limit;
- required attachment;
- reminder schedule;
- SLA target; at

### 8.4 Data quality and reconciliation

Mag-warning kapag:

- duplicate item code o serial number;
- zero quantity pero `Available` ang status;
- `Borrowed` ang item pero walang release record;
- returned quantity ay mas mataas sa released quantity;
- active borrowing ang item pero `Under Maintenance`; o

### 8.5 QR/barcode-assisted operations

Pagkatapos gumana ang basic release/return flow, maaaring magdagdag ng QR/barcode para sa:

- item verification;
- mabilis na release;
- mabilis na return;

- repair reporting.

### 8.6 Reports at management dashboard

Useful reports:

- most borrowed items;
- borrowing volume by user type;
- on-time return rate;
- overdue at no-show rate;
- damage/loss incidents;
- repair resolution time;
- request processing time;
- inventory movement;
- pending requests by department; at
- manual override frequency.

### 8.7 Requester feedback

Pagkatapos ma-close ang request, maaaring humingi ng short rating at comment para masukat ang GSO service. Dapat optional ito at hindi dapat makaapekto sa future eligibility ng user.

## 9. Future Scope: Facility, Vehicle, at Purchase

Hindi muna ito ang pangunahing target, ngunit maaaring gamitin ang parehong request/approval/reservation pattern pagkatapos ng Borrowing MVP.

### Facility reservation

```text
Request -> Schedule Check -> Approval -> Reservation -> Setup -> Event -> Inspection -> Close
```

Automation ideas:

- double booking prevention;
- temporary slot hold;
- permit/endorsement checklist;
- setup reminder;
- equipment checklist;
- post-event condition report; at
- automatic release ng cancelled slot.

### School vehicle request

```text
Request -> Trip Validation -> Approval -> Vehicle/Driver Assignment -> Trip -> Completion
```

Automation ideas:

- vehicle availability check;
- passenger capacity check;
- overlapping trip warning;
- driver schedule conflict warning;
- trip reminder;
- mileage/fuel prompt; at
- trip completion record.

### Purchase request

```text
Request -> Review -> Approval Routing -> Procurement -> Received -> Inventory Entry -> Close
```

Automation ideas:

- duplicate pending purchase warning;
- estimated total calculation;
- approval routing by amount threshold;
- required justification and attachments;
- pending approver reminder; at
- suggestion na gumawa ng inventory record kapag natanggap na ang item.

Ang tatlong process na ito ay dapat idagdag lamang kapag stable na ang request queue, permissions, audit, at notification foundation.

## 10. Secure Tracking at Attachments

### Access rules

- Ang requester ay sariling requests lamang ang makikita.
- Ang GSO Staff ay requests na sakop lamang ng permission.
- Ang supervisor ay assigned o escalated requests.
- Ang IT Admin ay users, roles, permissions, at audit access.
- Ang request code lamang ay hindi sapat para ma-access ang private record.

### Attachment rules

- Validate allowed file type at maximum file size.
- Secure storage, hindi public URL.
- Authorization check bago mag-view o mag-download.
- I-record ang upload, download, review, at delete action.
- Huwag awtomatikong mag-delete ng file na bahagi ng audit o active incident.
- Magkaroon ng retention policy para sa completed requests.

### Human-control safeguards

- Huwag automatic na i-approve ang high-value o restricted item.
- Huwag automatic na i-release ang physical item.
- Huwag automatic na magdeklara ng lost item o mag-charge ng penalty.
- Huwag automatic na mag-blacklist sa unang no-show.
- Lahat ng manual override ay kailangan ng reason at audit record.

## 11. Scheduled Automation Plan

| Frequency | Suggested automation |
|---|---|
| Every few minutes | Expire temporary holds at retry failed notifications |
| Hourly | Update due/overdue status at detect missed pickup window |
| Daily | Due reminders, no-show follow-ups, repair reminders, at data-quality checks |
| Weekly | GSO workload summary at long-pending request list |
| Monthly | Borrowing, inventory, repair, overdue, at request-volume report |
| On demand | Inventory reconciliation, resend notification, export report, o manual review |

### Scheduled job safeguards

- Dapat safe ulitin ang job nang walang duplicate status update o notification.
- Dapat may last run, result, error message, at retry record.
- Ang failed job ay dapat makita ng authorized admin o GSO supervisor.
- Hindi dapat magbura ng business history ang cleanup process.

1. **Home Page GSO Request Center**
2. **Borrowing MVP**
3. **Availability and Reservation Automation**
4. **GSO Approval and Release Permissions**
